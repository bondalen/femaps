# Проект: Оцифровка карт Lage Ost / Lage West

> Документ сформирован по итогам первичного обсуждения проекта.  
> Дата последнего обновления: 26.05.2026

---

## 1. Цель проекта

Создание **бесшовного векторного набора данных** на основе немецких оперативных карт Верховного командования сухопутных войск (OKH) **«Lage Ost»** и **«Lage West»** масштаба **1:1 000 000**, пригодного для:

- формирования листов карт в произвольных проекциях;
- отображения на веб-картах / тайловых сервисах.

---

## 2. Исходные картографические материалы

### 2.1. Серия карт

| Параметр | Значение |
|----------|----------|
| Серия | Weltkarte 1:1 000 000 (Всемирная карта), немецкое ОКХ |
| Масштаб | 1:1 000 000 |
| Охват | Lage Ost — восточный ТВД; Lage West — западный ТВД |
| Период | Вторая мировая война (1939–1945) |

### 2.2. Геодезические параметры

| Параметр | Значение |
|----------|----------|
| Проекция | Равноугольная коническая Ламберта (Lambert Conformal Conic) |
| Осевые меридианы | Индивидуальны для каждой зоны / листа |
| Датум | Потсдамский (Potsdam Datum) |
| Эллипсоид | Hayford (1909) или Bessel (1841), зависит от листа |
| Координатная сетка на карте | Градусная, от Гринвича |

> ⚠️ **Важно:** Не путать градусную сетку с немецкой военной сеткой
> **Gradnetzmeldeverfahren** — она наносилась поверх для передачи координат целей
> и не является системой координат карты.

### 2.3. Рекомендации по привязке (геореференсированию)

- Привязку выполнять по **явным пересечениям градусной сетки** (координатным крестам).
- Указывать **проекцию Lambert Conformal Conic** с осевым меридианом конкретного листа.
- После привязки — трансформировать в **WGS 84** или рабочую СК проекта.
- Инструмент: **Слой → Привязчик растров** (QGIS ≥ 3.26).

### 2.3.1. Практика georef и зоны оцифровки (выработано на листе 44-12-01)

На крупном листе (~15°×11°) привязка **полиномом 2 / TPS** надёжна **локально** —
вокруг контрольных точек и внутри ячеек с полным набором GCP.

| Правило | Содержание |
|---------|------------|
| **Минимальная зона оцифровки** | Квадрат **1°×1°** (пересечения меридиана и параллели), у которого **все 4 угла** отмечены GCP при georef |
| **Края листа** | Ячейки с «обрезанным» контуром (нет одного или нескольких угловых GCP) — **не оцифровывать** с этого листа; искать полный квадрат на том же или соседнем листе |
| **Контроль georef** | Векторная сетка 1° в **EPSG:4326** с целочисленным extent (напр. `-7, 41, 10, 55`) должна совпадать с напечатанной градусной сеткой |
| **Контроль по OSM** | Береговая линия OSM — **дополнительный** контроль; в полной ячейке разнонаправленные расхождения указывают на обобщение карты 1:1M и эпоху, а не на системный сбой привязки |
| **Выход georef** | GeoTIFF в **EPSG:4326**; проект QGIS для текущей работы — **WGS 84** |

Параметры georef стартового листа (пилот): ~20 GCP на пересечениях сетки,
CRS точек и выхода — EPSG:4326, невязки GCP ≤ ~5 пикс. (~160 м на местности).

### 2.4. Текущий стартовый лист

Для начала работ выбран лист:

```text
maps/rastr/001_000_000/OKH/LW/1944/12/44-12-01 1M Lage West.tif
```

| Параметр | Значение |
|----------|----------|
| Серия | Lage West |
| Район | Frankreich, юг Франции |
| Дата | 01.12.1944 |
| Масштаб | 1:1 000 000 |
| Формат | TIFF / GeoTIFF-контейнер без внутренней геопривязки |
| Размер | 5561 × 6605 пикселей |
| Разрешение | 800 dpi |
| Цвет | 24-bit RGB |
| Размер файла | ~105 МБ |

Файл технически пригоден как исходный растр: читается GDAL, имеет хорошее
разрешение и не содержит встроенной ошибочной геопривязки. Привязка будет
создаваться вручную по градусной сетке.

Основной стартовый слой для оцифровки:

- **железные дороги юга Франции**.

Выбранный участок визуально достаточно свободен от оперативной обстановки,
поэтому подходит для отработки методики привязки, трассировки линейных объектов
и последующей проверки топологии.

### 2.5. Принцип выбора растров для геоосновы

Для геоосновы не следует автоматически брать самый поздний или самый полный
оперативный лист. Для каждого района / листа разграфки выбирается лучший
экземпляр по совокупности критериев:

- качество скана и разрешение;
- читаемость географической основы;
- минимальная насыщенность оперативными знаками;
- отсутствие перекрытия дорог, железных дорог и населённых пунктов стрелками,
  фронтовыми линиями, штриховкой и подписями оперативной обстановки;
- предпочтение TIFF/PNG перед JPG при сопоставимом содержании.

Остальные растры той же территории сохраняются как исторические варианты и
могут понадобиться позже для оцифровки слоёв оперативной обстановки.

## 3. Состав оцифровываемых слоёв

### 3.1. Искусственные географические объекты (оцифровываются из Lage)

Эти объекты с 1939–1945 гг. могли **измениться** (включая наименования),
поэтому их оцифровка из карт является основной задачей.

| Слой | Тип геометрии | Примечания |
|------|--------------|------------|
| Населённые пункты | Точка / Полигон | Включая наименования эпохи |
| Дороги | Линия | Автодороги, шоссе |
| **Железные дороги** | Линия | Первый слой для отработки методики |
| Прочие ИГО | По ситуации | Аэродромы, порты, укрепления и т.п. |

### 3.2. Природные объекты (берутся из внешних источников, не оцифровываются)

Природные объекты **практически не изменились** — их целесообразно получать
из современных открытых источников.

| Объект | Рекомендуемый источник |
|--------|------------------------|
| Гидрография (реки, озёра) | OSM (Geofabrik), Natural Earth |
| Рельеф (горы, впадины) | Copernicus DEM, SRTM |
| Леса, болота | OSM, Copernicus Land Cover |
| Береговая линия | Natural Earth, OSM |

## 5. Программный стек

### 5.1. GIS-платформа

| Компонент | Версия | Установка | Статус |
|-----------|--------|-----------|--------|
| **QGIS LTR** | 3.44.10 | `winget install OSGeo.QGIS_LTR --location "D:\Program_Files_LTR"` | Установить |
| QGIS 4.0.2 | 4.0.2 | уже в `D:\Program_Files\QGIS` | Установлен (оставить) |

QGIS 3.44 LTR используется как **основная рабочая платформа** — полная совместимость
с AI-плагинами. QGIS 4.0 можно держать параллельно для тестирования.

### 5.2. AI-плагины в QGIS 3.44 LTR

Устанавливаются через **Модули → Управление и установка модулей**.  
Для отображения всех плагинов включить **«Показывать экспериментальные»**.

| Плагин | Назначение | Требования к GPU | Приоритет |
|--------|-----------|-----------------|-----------|
| **AI Segmentation** (TerraLab) | Клик → полигон: НП, кварталы, площадные объекты | Только CPU | ★ Первый |
| **Deepness** | Батч-детекция ONNX по тайлам: дороги, строения | **DirectML (AMD)** | ★ Второй |
| **GeoOSAM** | SAM 2.1 / SAM 3, интерактив, авто-определение железа | CPU или DirectML | ★ Третий |
| **Geo-SAM** | SAM для больших площадей, предварительное кодирование | CPU | Дополнительно |
| **ArchaeoTrace** | Интерактивная трассировка линий (OpenCV Canny / SAM) | CPU (OpenCV / MobileSAM) | Вспомогательный; пилот ж/д 1:1M — качество и скорость ≈ ручной |

> ⚠️ AI — **помощник, не автопилот.** Военные карты содержат штриховку, тактические знаки
> и сетку Gradnetzmeldeverfahren, из-за чего нейросети часто ошибаются.
> Обязательна ручная проверка и правка каждого автоматически созданного объекта.

### 5.3. База данных (Docker)

Уже запущен `postgres:16` — для GIS создаётся **отдельный контейнер** с PostGIS,
чтобы не затрагивать существующие данные.

```yaml
# фрагмент docker-compose для добавления в проект
services:
  maps-postgis:
    image: postgis/postgis:16-3.5
    container_name: maps-postgis
    ports:
      - "5434:5432"          # 5434 — не конфликтует с существующим postgres
    environment:
      POSTGRES_DB: maps_db
      POSTGRES_USER: maps_user
      POSTGRES_PASSWORD: maps_pass
    volumes:
      - maps_postgis_data:/var/lib/postgresql/data
    restart: unless-stopped

  maps-martin:
    image: ghcr.io/maplibre/martin:latest
    container_name: maps-martin
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://maps_user:maps_pass@maps-postgis/maps_db
    depends_on:
      - maps-postgis
    restart: unless-stopped

volumes:
  maps_postgis_data:
```

| Компонент | Роль |
|-----------|------|
| **PostGIS 16-3.5** | Хранение бесшовного векторного набора данных |
| **Martin** (MapLibre) | Отдача vector tiles (MVT) и GeoJSON API |

### 5.4. Python-пайплайн (WSL Ubuntu 24.04 LTS)

Ubuntu 24.04 уже запущен в WSL2. Python 3.12.3 установлен.

```bash
# Установка GDAL и системных зависимостей
sudo apt update
sudo apt install gdal-bin python3-gdal python3-pip python3-venv

# Создание виртуального окружения проекта
python3 -m venv ~/venvs/maps
source ~/venvs/maps/bin/activate

# Основные библиотеки
pip install \
  rasterio \
  geopandas \
  shapely \
  fiona \
  pyproj \
  opencv-python-headless \
  jupyterlab \
  segment-geospatial       # SAM2 + гео-интеграция (samgeo)
```

| Библиотека | Назначение |
|-----------|-----------|
| `rasterio` | Чтение / запись растров (GeoTIFF, сканы карт) |
| `geopandas` | Обработка векторных данных |
| `shapely` | Геометрические операции |
| `pyproj` | Перепроецирование, трансформации СК |
| `opencv-python` | Предобработка растров (удаление сетки и т.п.) |
| `segment-geospatial` | SAM2 с геопривязкой (samgeo) |
| `jupyterlab` | Интерактивный Python-пайплайн |

## 7. Рабочий процесс оцифровки

| № | Шаг | Инструмент | Среда |
|---|-----|-----------|-------|
| 1 | Получить сканы листов Lage | Архивы (mapywig.org и др.) | — |
| 2 | Выбрать лучший растр для геоосновы конкретного листа / района | Визуальная оценка + инвентаризация | QGIS / Python |
| 3 | Привязка выбранного листа по градусной сетке | Georeferencer (QGIS 3.44) → EPSG:4326 | Windows |
| 3a | Выбор ячейки 1°×1° с 4 угловыми GCP для оцифровки | Проверка сетки + OSM (дополнительно) | QGIS |
| 4 | Оцифровка первого слоя: железные дороги юга Франции | Только внутри полных ячеек 1°×1°; трассировка по растру + AI | QGIS |
| 5 | Виртуальная мозаика привязанных листов | `gdalbuildvrt` | WSL / GDAL |
| 6 | AI-оцифровка НП и площадных объектов | AI Segmentation | QGIS |
| 7 | AI-оцифровка дорог и ж/д | **Гибрид:** цветовая маска + skeleton (WSL) или GeoOSAM → centerline; ArchaeoTrace — опционально; ручная правка класса и топологии | QGIS / WSL |
| 8 | Батч-детекция по тайлам (при наличии модели) | Deepness (DirectML) | QGIS |
| 9 | Контроль топологии и сшивка стыков | Проверка геометрии / geopandas | QGIS / WSL |
| 10 | Загрузка в базу данных | `ogr2ogr` → PostGIS | WSL |
| 11 | Публикация тайлов | Martin → MVT | Docker |
| 12 | Природные объекты | OSM Geofabrik / Copernicus | Без оцифровки |
