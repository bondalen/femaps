## 0. Цель

Построить в schema `org` **реляционный жизненный цикл организации** (государство, позже соединения ВС и др. типы) по образцу рабочего шаблона `rgTax` / `rgTaxReor*`, с минимальной адаптацией:

- лицо `org` + способы создания/прекращения;  
- таблицы **правопреемства** (`Reor*`) как основа основ;  
- **преобразование не меняет id** (в отличие от ЕГРЮЛ);  
- расширение — итерациями и прецедентами (сначала ЖЦ+Reor, затем длящиеся связи, затем оккупация).

### Критерий закрытия итерации 0

1. DDL лица, справочников frm/trm и reor-таблиц в `maps_db.org`.  
2. Правило convert = same id зафиксировано в доке и отражено в схеме (нет обязательной пары id для преобразования).  
3. На данных воспроизводим прецедент **присоединения с правопреемником** (Австрия → Германия или учебный стенд).  
4. В схему итерации 0 **не** входят Membership / occupation / налоговые поля.

### Критерий более поздних итераций (ориентир)

| Итерация | Критерий |
|----------|----------|
| 1 | Несколько прецедентов на каркасе 0 (convert JP; absorb AT; …) без ломки DDL |
| 2 | Длящийся состав (`part_of` / Membership) на прецеденте Пруссия⊂Германия |
| 3+ | Оккупация / типы `org` / стык с ВС — по кейсам |

## 2. Принципы (кратко)

1. **Правопреемство ≠ состав.** `ReorAcqui` — факт прекращения-присоединения; `part_of` — пока оба живы.  
2. **Основа — Reor* + kind на лице**, не «достаточно справочников kind».  
3. **`org` шире суверена**; type откладываем лёгким справочником, не отдельным ЖЦ.  
4. **convert = same id**; единственная жёсткая адаптация относительно `rgTaxReorTrans`.  
5. **Соседний `name_form`** не заменяет полные имена и не кодирует absorb/merge.  
6. **Итерации**; комбинации 2.6–2.9 можно завести пустым каркасом таблиц сразу, наполнять по кейсам.
