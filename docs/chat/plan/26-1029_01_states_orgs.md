## 0. Объём чата (жёсткие границы)

### Входит

| Область | Содержание |
|---------|------------|
| Государства / суверенитеты | Корневые узлы учёта (Reich, UK, USA, USSR, France… по мере надобности) |
| Структуры государства (военное ядро) | OKW / OKH, виды ВС, объединения и соединения (до уровня, нужного для учёта) |
| Коалиции и надстройки | SHAEF, Expeditionary Force, объединённые штабы ТВД, приданые союзные армии |
| Два графа связей | **Состав** (дерево/лес принадлежности) и **управление** (DAG подчинения) |
| Темпоральность | `valid_from` / `valid_to` на организациях и рёбрах |
| Штатные шаблоны | Типы единиц и опционально коды KStN / аналогов — без обязательного заполнения численности |
| Реляционная модель | Схема SQL + справочники + пилотные данные (Запад / коалиция 1944) |

### Не входит (явно вне чата)

| Область | Почему |
|---------|--------|
| Геопривязка, слои карт, полосы обороны | Отдельный контур после стабилизации оргграфа |
| Полное гражданское дерево (МВД, школы, Рейхстаг) | Не нужно для учёта ВС/коалиций |
| Партия / Allgemeine SS как гражданский слой | Только вооружённые «равные гос.» (напр. Waffen-SS), если появятся на ТВД |
| Онтологии OWL/RDF, Fuseki, entity resolution | Только если реляционная модель упрётся |
| Персоны (Роммель, Гитлер…) | Опционально позже; v1 — организации и связи |
| Soll/Ist численность «до последнего хиви» | Поля зарезервировать; массовый ввод — не цель чата |
| Martin / тайлы / QGIS-слои оргструктуры | Не требуется без гео |

### Критерий выхода из чата

Запросом к БД на выбранную дату (напр. `1944-12-01`) можно:

1. Развернуть дерево **состава** от суверена до выбранного уровня (армия / корпус — по наполнению пилота).  
2. Развернуть DAG **управления** для того же среза (включая коалиционный штаб → национальные армии).  
3. Отличить «принадлежит Heer» от «оперативно под SHAEF / OB West».  
4. Не получить двойной счёт одной единицы в двух корнях состава.

Если появятся связи, которые нельзя выразить без классов/ограничений выше SQL+CHECK+EXCLUDE — тогда отдельное решение об онтологии.

## 1. Уточнённая модель (реляционный DAG)

### 1.1. Сущности

| Сущность | Назначение |
|----------|------------|
| `sovereign` | Государство / суверенный корень учёта |
| `org_system` | Система внутри суверена: Heer, Luftwaffe, US Army, RAF…; отдельно `coalition` для надгосударственных штабов |
| `org_kind` | Справочник видов: ministry_mil, high_command, army_group, army, corps, division, expeditionary_force, combined_hq… |
| `org_template` | Типовой шаблон (аналог KStN-класса): необязательный `external_code`, штатная ёмкость позже |
| `organization` | Конкретная единица: «7. Armee», «21st Army Group», «SHAEF» |
| `org_name` | Исторические / языковые имена и алиасы |
| `org_link` | Ребро графа: `src_org` → `dst_org`, тип связи, интервал дат |

### 1.2. Типы связей (`org_link.link_type`) — минимум

| link_type | Граф | Смысл |
|-----------|------|--------|
| `part_of` | Состав | Жёсткая принадлежность (дерево/лес внутри суверена или системы) |
| `commands` | Управление | Оперативное подчинение (DAG; допускает dual-hat и смену вышестоящего) |
| `attached_to` | Управление | Придано / временно подчинено (союзники, SS при AOK) |
| `coalition_member` | Коалиция | Участник коалиционного штаба / экспедиционных сил (не путать с `part_of`) |

Правило анти-двойного счёта: **сумма «под ружьём»** = листья по `part_of` нужных `org_system`; рёбра `commands` / `attached_to` / `coalition_member` **не** добавляют людей.

### 1.3. Коалиции и экспедиционные силы

Моделировать как `organization` с `org_system.kind = coalition` (или `org_kind = combined_hq` / `expeditionary_force`), без отдельной «магии»:

- SHAEF, AEAF, 21st Army Group — узлы коалиции / союзного командования.  
- Национальная армия остаётся в `part_of` своего суверена.  
- Связь с коалицией — `commands` или `coalition_member` на дату.  
- Исторические переименования / переформирования — новая `organization` или смена имён + рёбер с датами (не затирать историю).

### 1.4. Совмещение должностей штаба (OB West / HGr D)

Два допустимых паттерна (выбрать один в DDL и зафиксировать):

1. **Две организации** + ребро `same_staff_as` / период personalunion; или  
2. **Одна организация состава** + второе ребро `commands` с ролью `dual_hat`.

Для пилота предпочтителен вариант 2 (проще), с возможностью позже ввести `same_staff_as`.

### 1.5. Схема БД

Отдельная schema, чтобы не смешивать с геослоями:

```text
org.*     -- этот чат
public.*  -- railways и пр. (не трогаем)
```

Геоколонок в `org.*` нет.

## 4. Риски и правила ведения

1. **Не смешивать** `part_of` и `commands` в одной семантике «parent_id».  
2. **Не класть** коалиционный штаб внутрь национального `part_of` как единственный корень численности.  
3. Любое изменение истории — **новые интервалы**, не UPDATE без `valid_to`.  
4. Расширение вниз до дивизий — по необходимости пилота, не «весь Heer 1944».  
5. Онтологии — план B, не параллельный трек.
