# Раздел `org`: суверены и основы официальных имён

Документация модели данных и уровня представления для учёта **государств (суверенов)** и **основ их официальных наименований** (республика, королевство, рейх, empire…).  

Геопривязка, полосы обороны и полный оргграф ВС/коалиций — **вне** этого контура (см. план чата). Онтологии OWL — только если реляционная модель упрётся.

**БД:** PostgreSQL / PostGIS `maps_db` (`localhost:5434`), schema **`org`**.  
**Геометрии в `org` нет.**

---

## 1. Цель

1. Отделить **суверена** (Япония, Германия…) от **формулы имени** (`empire`, `reich`, `republic`…).  
2. Хранить формулы как абстрактные вершины с ярлыками по языкам.  
3. Связывать суверена с формулой **по времени**.  
4. Строить **разные деревья представления** (de / en / …) из одного смыслового графа рёбер — без дублирования «немецкой» и «английской» онтологии и без введения англичанам сущностей reich/kaiserreich.

Позже на тех же суверенах наращиваются структуры ВС и коалиций (состав = дерево, управление = DAG) — отдельными таблицами.

---

## 2. Принципы

| # | Принцип |
|---|--------|
| P1 | Основа имени ≠ государство. Франция не «ребёнок» типа `republic` в таксономии типов; она **связана** с `republic` на интервале дат. |
| P2 | Код/`id` вершины языконезависимы. Переводы — в ярлыках; немецкое словосложение (*Königreich* / *Kaiserreich*) не задаёт глобальную таксономию смыслов. |
| P3 | На смысловом уровне допустимо: **`reich` уже, чем `empire`** (ребро `empire → reich`). Отдельное ребро `state → reich` для de **не обязательно**, если алгоритм туннелей даёт нужную проекцию. |
| P4 | Иерархия для UI **существует относительно языка** и **вычисляется**; учёт суверена всегда к `name_form`, не к пути `1.1.2`. |
| P5 | Один суверен — много периодов формулы (Япония: empire → state; Германия: kaiserreich / reich / …). Лист представления = период (`sovereign_name_form`), не вся сущность. |
| P6 | Структурные номера (`1.1.#2`) только на уровне представления, не первичные ключи. |

## 3. Логическая модель (целевая)

Целевая модель рёбер уточнена по [эскизу представления](26-1101_presentation_sketch.md) и обсуждению туннелей.  
**В БД на момент написания** ещё действует вариант `010`: `language_code` прямо на `name_form_edge`. Миграция к «одно ребро + метки языков» — следующий шаг DDL.

### 3.1. Сущности

```text
language                 — язык UI/ярлыков (de, en, ru, …)
name_form                — абстрактная основа имени (state, reich, empire, …)
name_form_label          — name_form × language → строка (Staat, empire, рейх)
name_form_edge           — смысловое ребро parent → child (один раз)
name_form_edge_label     — какие языки делают ребро «явным» в UI  [целевое]
sovereign                — государство / суверен учёта
sovereign_name_form      — суверен × name_form × [valid_from, valid_to]
```

Позже (не обязательно в v0): `sovereign_name` — полное официальное наименование × язык × даты.

### 3.2. Текущие таблицы в Postgres (`010`)

| Таблица | Содержание |
|--------|------------|
| `org.language` | языки (seed: de, en, ru, fr, ja) |
| `org.name_form` | вершины (`code`, `assignable`) |
| `org.name_form_label` | ярлыки вершин |
| `org.name_form_edge` | рёбра **с** `language_code` на ребре (промежуточная схема) |
| `org.sovereign` | суверены |
| `org.sovereign_name_form` | периоды формулы имени |

## 4. Уровень представления (алгоритм)

Вход: язык L (и опционально дата-срез).  
Выход: дерево с ветками `name_form` и листьями-периодами суверенов (`#n`).

### 4.1. Явное ребро и туннель

- Ребро **явное в L**, если у него есть метка языка L (`edge_label` в целевой модели; в схеме `010` — совпадение `language_code`).  
- Иначе ребро при обходе — **туннель**: путь не обрывается, промежуточный узел в UI может не рисоваться.

### 4.2. Правила

1. Обход потомков от корня (`state` / `Staat`) по всему DAG; туннели разрешены.  
2. Узел V **показан как ветка** в L, если есть `name_form_label(L)` и существует путь от корня, где **последнее** ребро перед V явное в L (корень — исключение).  
3. Parent в UI = ближайший **показанный** предок.  
4. Лист периода вешается на ближайшего показанного предка своего `name_form` (если form показан — на него).  
5. Несколько путей → меньше туннелей, затем короче путь / `sort_order` (прямой `state → kingdom` для en предпочтительнее длинного через `reich`).

### 4.3. Эталонный эффект без ребра `state → reich`

Цепочка: `state → empire` (явно en) → `reich` (явно de).

| Язык | Видимая ветка | Куда падает период с `name_form = reich` (напр. Großdeutsches Reich) |
|------|---------------|---------------------------------------------------------------------|
| en | `state → empire` | под `empire` (`reich` скрыт туннелем) |
| de | `Staat → Reich` | под `reich` (`empire` скрыт туннелем) |

Смысл: на независимом уровне reich уже empire; UI языка выбирает, какой этаж показать.

Эскизы желаемых полных деревьев: [26-1101_presentation_sketch.md](26-1101_presentation_sketch.md).

## 5. Чего раздел сознательно не делает

- не моделирует режим (диктатура, демократия) и не равен «форме правления» в политологическом смысле;  
- не подменяет официальное полное имя государства ярлыком типа (`Reich` ≠ «Großdeutsches Reich»);  
- не хранит геометрий и оперативную обстановку карт;  
- не смешивает коалиции (SHAEF) с суверенами.

## 7. Связь с проектом карт

Оцифровка Lage Ost/West опирается на привязку объектов обстановки к **структуре сил**. Стабильные `sovereign` и (далее) организации ВС — справочник для атрибутов полос и знаков **без** смешения состава и оперативного подчинения. Раздел `org` — первый камень этого справочника.
